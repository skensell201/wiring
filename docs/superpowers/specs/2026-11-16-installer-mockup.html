Wiring · installer

Three installer directions, in the app's own language

Every surface below uses the tokens the app already ships — Midnight Plum canvas, Shadow Plum cards, Lavender Spark accent, Signal Green for the one action a screen asks for, Geist, and the heptagon mark. The flow is the same in all three: welcome → destination → components → progress → done. What changes is how much chrome stands between the user and the install.

A Native, repainted B Exact, in-app C Cinematic
Direction A

A — Native, repainted

The classic Windows wizard, every surface repainted in the app's palette. No sidebar image, no stock buttons: the installer keeps the shape users already know, but reads as part of the product. On Linux the same design becomes the first-run sheet.

NSIS custom template no extra binary Win32 controls
  • Built with: a custom .nsi template (bundle.windows.nsis.template) with SetCtlColors, custom fonts and image-drawn buttons. No new dependency, no new binary to sign.
  • Ceiling: Win32 controls cannot be truly pixel-perfect — button corners, focus rings and text rendering stay native. Close to the app, not identical to it.
  • Linux: a .deb installs silently, so there is no OS installer to theme. The first-run sheet inside the app is the only surface that can carry the brand.
Direction B

B — Exact, in-app

The installer is the app: the same React components, the same tokens, the same Geist, in a small Tauri window that then performs the install. Nothing is re-drawn by hand, so the installer can never drift from the product.

pixel-exact second binary one design system
  • Built with: a second Tauri app in the same workspace, sharing theme.css, the Button and EmptyState components, and the same mark.svg.
  • Cost: a second binary to build, sign and notarise on every release, plus a second updater channel to keep alive. It must never show an update prompt of its own.
  • Win: the installer and the app can never disagree about a colour, a radius or a font — the drift risk in Direction A disappears entirely.
Direction C

C — Cinematic

The installer says one thing at a time. No fields, no checkboxes, no wizard chrome — just the mark, a single line of copy and a progress rule. Everything else is decided for the user, because there was never much to decide.

least chrome fastest to read no destination choice
  • Built with: one NSIS page set with a full-bleed bitmap, and the app's own first-run sheet on Linux. The smallest surface to keep on-brand.
  • Trade-off: the user cannot choose where Wiring goes, and cannot pick what gets installed. For a single-binary app that installs to one place, that may be the right default — but it must be stated, not silently assumed.
  • Risk: with so little on screen, a stalled install looks broken. The copy has to name what is happening right now.
Separate from the three directions

The icon, which the installer currently does not use

bundle.windows.nsis.installerIcon is not set, so -setup.exe ships with Tauri's default icon — which is why Chrome's download list shows a globe next to Wiring_0.5.1_x64-setup.exe. The mark already exists and is good; it is simply not reaching the places a user sees first.

Recommendation. Direction A for Windows, Direction C's restraint for Linux's first run. A gives the installer the app's character without turning the installer into a second application to sign and update; C keeps the Linux surface — which cannot be themed at the OS level — from pretending to be an installer at all. Direction B is the only one that is pixel-exact, and it pays for that with a permanently maintained second binary.

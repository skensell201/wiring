# Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VitePress site in `site/` (served at https://wiringk8s.xyz): a landing page with an OS-detected Download button, and guide and developer docs that pull their text from the README and `docs/*.md`.

**Architecture:** `site/` is a self-contained VitePress 1.6.4 project with its own `package.json` and `pnpm-lock.yaml`. The app's dependency tree, `tsconfig.json` and Vitest config are not touched. The README gains `<!-- #region name -->` markers, and the docs pages include those regions with `<!--@include: ../../README.md#name-->`. VitePress pastes included text verbatim, so a small markdown-it plugin rewrites the README's repository-relative links. A Vitest guard fails on includes that VitePress would silently get wrong. The Doppler theme tokens map onto VitePress CSS variables, and the site is dark only. The landing page (`/`) is the user's approved interactive mockup, ported faithfully: `site/index.md` is `layout: false` plus a `Landing.vue` component tree, the mockup is committed, and a port script generates `landing.css` (its CSS, scoped under a `.wl` root class) and the Vue templates from it, so later layout polish carries over by re-running it. Its vanilla script is ported by hand into TypeScript modules that start in `onMounted` and stop in `onUnmounted`; a hash check catches a changed script. Its pure parts (sample data, layout, sort and filter) are unit-tested. A pure `pickAsset(assets, os)` chooses the installer, and the landing's Download button fetches the latest release in the browser. Before that fetch, and without JavaScript, the button links to the releases page. CI builds and tests the site. `site/deploy.sh` rsyncs the build to the droplet by hand.

**Tech Stack:** VitePress 1.6.4 (Vue 3.5, Vite 5.4), Vitest 3.2.7, `@vitejs/plugin-vue` 5.2.4, `@fontsource-variable/geist` and `geist-mono` 5.3.0, GSAP 3.15.0 (ScrollTrigger and ScrollSmoother), pnpm 9, Node 22, GitHub Actions, rsync and nginx on the droplet.

## Deviations from the spec

1. **Hosting (the user changed it twice):** there is no GitHub Pages and no `/wiring/` sub-path. The site has its own domain, **https://wiringk8s.xyz**, served by nginx on the user's DigitalOcean droplet (`root@137.184.51.178`), the same droplet as aftergram.cc and keyorra.com.
   - `base` is `/`.
   - `pages.yml` and `actions/deploy-pages` are dropped. CI builds and tests the site on pushes and pull requests but does not deploy.
   - `site/deploy.sh` builds the site and rsyncs it to `root@137.184.51.178:/var/www/wiring/`; the controller runs it by hand.
   - DNS already points `wiringk8s.xyz` and `www` at the droplet (DigitalOcean nameservers), so "After merge (controller)" only checks it with `dig`. The certificate, the nginx site, the repository homepage URL and the portfolio link are there too.
   - The README links to https://wiringk8s.xyz.
2. **Includes are pasted verbatim.** VitePress (`processIncludes`) does not rewrite relative links in included text, so the README's `docs/images/graph.png`, `LICENSE`, `examples/demo/…` and `docs/*.md`, and the `../…` links in `docs/code-signing.md`, would resolve against the including page. The result would be dead links or a build error. `site/.vitepress/repo-links.ts` is a markdown-it plugin that fixes this:
   - documents that have a site page link to that page;
   - screenshots link to `/images/…`, which `site/scripts/copy-assets.mjs` copies from `docs/images` into `site/public/images` before every dev run and build;
   - every other repository path links to GitHub (`tree/master/…` for folders, `blob/master/…` for files).
3. **Bad includes do not fail the build.** An include whose file is missing stays an HTML comment and renders nothing. One whose `#region` is missing includes the **whole** README. Neither is an error. `site/test/includes.test.ts` checks that every include's file and region exist. Dead links do fail `vitepress build`; this was verified.
4. **Developer docs are five pages, not three.** `docs/code-signing.md` and `docs/updates.md` each start with their own `#` title, so each gets a page of its own: Releasing, Code signing and Automatic updates, under a "Releasing" sidebar group. The guide's **Updates** page is the README's user-facing `updates` region, and links to the developer page.
5. **One README edit besides the markers:** the logs screenshot moves from after the Terminal paragraph to the end of the Logs list, so the `logs` region carries it. It sits two paragraphs higher, still in the Features section.
6. **Vitest 3.2.7 in `site/`, not the app's Vitest 5:** Vitest 5 needs Vite 6 or newer, and VitePress 1.6.4 is built on Vite 5. `vite` is pinned to `5.4.21` in `site/package.json`, so the site has a single Vite.
7. **`srcExclude` is not needed.** `srcDir` is `site/`, `docs/` lies outside it, and VitePress already skips `node_modules`. Dark only is `appearance: "force-dark"`, which hides the toggle. Code blocks use the bundled Shiki theme `dracula` (purple, pink, green and cyan) in place of the default `github-dark`, which pairs blue with yellow.
8. **The Namespaces and RBAC page** includes the `namespaces` region and, again, the `navigator` region (which holds the RBAC strike-through text), plus a two-sentence intro and a short pointer to the graph's RBAC chips. The README has no separate RBAC paragraph to include.

9. **The landing is the user's approved mockup, not the spec's `layout: home` page** (the user decided after the spec). It keeps the mockup's markup, CSS and behaviour, and replaces the spec's §3 landing:
   - The framed screenshot gives way to the live graph demo: hover tracing, a details panel, kind chips, **Break a pod** / **Fix it**, random restarts and edge flow.
   - The eight feature cards are the mockup's, with glyph icons on a gradient tile instead of Lucide SVGs (`site/public/icons` is dropped).
   - New sections: the "Tables and YAML" demo (sort, search, a row's YAML diff, Apply adds a pod), a final CTA and a Contacts section with a Copy button.
   - The hero's title and lead are the mockup's, and so is its own footer (Docs, Releases, GitHub, MIT license, Contacts). It replaces VitePress's footer on the landing only; the docs keep `themeConfig.footer`.
   - The eyebrow "v0.5.0 · …" is hard-coded as in the mockup; update it in `Landing.vue` with each release.
   - The custom `Layout.vue`, `HeroActions.vue` and `HomeScreenshot.vue` are dropped. The old `HeroActions` server-render test becomes `landing-download.test.ts`.
10. **`layout: false`** renders only the page's content: the default theme's `Layout.vue` has `<div v-if="frontmatter.layout !== false" class="Layout">…<Content v-else />`. Verified in a scratch build: the landing's HTML has no `VP…` class, while the docs pages keep the full theme.
11. **Fonts are self-hosted.** The mockup loads Geist and Geist Mono from Google Fonts. The site uses `@fontsource-variable/geist` and `@fontsource-variable/geist-mono`, the same typefaces, with no third-party request. `landing.css` names `"Geist Variable"` and `"Geist Mono Variable"` first.
12. **The landing is generated from the committed mockup, not copied into the plan.** The mockup may still be polished while this plan waits, for spacing, the footer or section order. Task 9 commits it as `docs/superpowers/specs/2026-10-06-landing-mockup.html`, and Task 12's `site/scripts/port-landing.py` derives the CSS and the Vue templates from it with mechanical, asserted rules. The demos' data and behaviour are ported to TypeScript by hand (Tasks 9 and 10) from the mockup's `<script>`. Task 9 checks that script's SHA-256 against the version this plan was ported from, and says how to carry over any change. `site/scripts/check-landing.mjs` compares the result with the mockup in headless Chrome.
13. **Scoped CSS.** The mockup's global rules (`:root`, `body`, `*`, `a`, `button`, `h1`, `h2`, `section`, `table`, `footer`, `code` …) are prefixed with `.wl`, the landing's root element, and its keyframes are renamed `wl-flow`, `wl-blink` and `wl-rowin`. Three rules undo VitePress's base reset where it differs from the browser defaults the mockup was designed on: `p` margins, the `h3` line height and the `b` weight. Measured in the scratch build, every section's top and height matched the mockup to the pixel at 1440 px and at 390 px. Against a later polish of the mockup, they matched at 1440 px and were within 2 px at 390 px.
14. **GSAP ScrollSmoother is kept**, from npm (`gsap` 3.15.0; `gsap/ScrollSmoother` and `gsap/ScrollTrigger` ship in the free package):
   - It is imported dynamically in `onMounted`, so the server build never loads it and the page's own chunk does not carry it. `onUnmounted` kills it, which restores `body`'s height before VitePress shows the next page.
   - It is skipped for `prefers-reduced-motion`.
   - VitePress's router intercepts same-origin link clicks in a capturing `window` listener and would scroll hash links itself with the docs' 134 px offset. It skips links that have a `target` attribute, so the landing's in-page links carry `target="_self"` and the landing scrolls them with the mockup's `top 24px`.
   - Arriving on `/#contacts`, from the docs' Contacts link or by URL, lands on the section once the smoother exists. The mockup did not handle this.
   - GSAP's licence is GSAP's "Standard no-charge" licence, not MIT. It allows this free, open-source use.
15. **The Download button** uses Task 8's tested `detectOs` / `pickAsset` / `fallbackDownload`:
   - The server renders the fallback: **Download Wiring** → the latest release, and "For macOS · Windows · build from source on Linux · all releases". The mockup shipped a static "Download for macOS" instead.
   - In the browser, macOS and Windows get the mockup's labels and lines, and both installers link straight to the files once the GitHub API answers. The mockup only changed the label.
   - Linux gets **Build from source**, which links to `/develop/`, not to the README's GitHub anchor.
   - The final CTA's "Download Wiring" stays a link to the latest release, as in the mockup.
16. **Links:** the mockup's "Docs" and "Read the docs" pointed at its footer (and, in the deployed interim copy, at the GitHub README); they go to `/guide/getting-started`, the guide's first page (there is no `/guide/` index). The feature cards' placeholder anchors go to their guide pages, except "Tables and YAML", which keeps `#tables`.
17. **Contacts on the docs pages:** a **Contacts** nav item (→ `/#contacts`) and a second `themeConfig.footer` line with the email, Telegram, GitHub and LinkedIn. VitePress hides its footer on pages with a sidebar, which is every guide and develop page, so `custom.css` shows it there, offset like the content.
18. **Rebase first.** `feat/site` branched before `6029a08 Replace the logo with the Cutout mark`, so "Before Task 1" rebases it onto `master`. Otherwise `/mark.svg` would be the old logo.
19. **Task 2's `custom.css` drops** the `VPFeature`, `--vp-home-hero-*` and `.steps` rules, which only served the old home layout. The bare `.steps` rule would also have matched the landing's own `.steps`.

- [ ] **Step 4: Implement `site/.vitepress/repo-links.ts`**

```ts
// The README and docs/*.md are written for GitHub, so their relative links point into the
// repository. VitePress pastes included text as-is, which would resolve those links against the
// including page. This rewrites them: documents that have a site page link to it, screenshots
// come from the public folder, and everything else in the repository links to GitHub.
import type { MarkdownRenderer } from "vitepress";

export const REPO_URL = "https://github.com/skensell201/wiring";

const PAGES: Record<string, string> = {
  "README.md": "/guide/getting-started",
  "docs/ipc-contract.md": "/develop/ipc-contract",
  "docs/code-signing.md": "/develop/code-signing",
  "docs/updates.md": "/develop/updates",
};

const REPO_PREFIXES = ["docs/", "examples/", ".github/", "src/", "src-tauri/"];
const REPO_FILES = ["LICENSE", "README.md", "package.json"];

/** The site URL for a repository-relative link, or null to leave the link alone. */
export function rewriteRepoLink(href: string): string | null {
  if (/^[a-z][a-z0-9+.-]*:/i.test(href) || href.startsWith("/") || href.startsWith("#")) return null;
  // docs/*.md link to the repository root with "../".
  const path = href.replace(/^\.\//, "").replace(/^\.\.\//, "");
  const hashAt = path.indexOf("#");
  const file = hashAt === -1 ? path : path.slice(0, hashAt);
  const hash = hashAt === -1 ? "" : path.slice(hashAt);
  if (file in PAGES) return PAGES[file] + hash;
  if (file.startsWith("docs/images/")) return "/images/" + file.slice("docs/images/".length);
  if (REPO_FILES.includes(file) || REPO_PREFIXES.some((p) => file.startsWith(p))) {
    return `${REPO_URL}/${file.endsWith("/") ? "tree" : "blob"}/master/${file}${hash}`;
  }
  return null;
}

/** markdown-it plugin: applies rewriteRepoLink to every link href and image src. */
export function repoLinks(md: MarkdownRenderer): void {
  md.core.ruler.push("wiring_repo_links", (state) => {
    for (const block of state.tokens) {
      for (const token of block.children ?? []) {
        const attr = token.type === "link_open" ? "href" : token.type === "image" ? "src" : null;
        if (!attr) continue;
        const value = token.attrGet(attr);
        const rewritten = value === null ? null : rewriteRepoLink(value);
        if (rewritten !== null) token.attrSet(attr, rewritten);
      }
    }
  });
}
```

The core rule runs after parsing and before rendering. VitePress's own link renderer (base, clean URLs, the dead-link check) therefore sees the rewritten hrefs. Absolute `/images/…` paths are served from `site/public`.

```ts
// Picks the installer to offer on the landing page. Pure, so it is unit-tested; the component
// that fetches the latest release lives in components/LandingDownload.vue.

export type Os = "mac" | "windows" | "linux" | "unknown";

export interface ReleaseAsset {
  name: string;
  browser_download_url: string;
}

export interface Download {
  /** What the button says, e.g. "Download for macOS". */
  label: string;
  href: string;
  /** "asset": a direct installer link; "source": the build instructions; "releases": the list. */
  kind: "asset" | "source" | "releases";
}

export const RELEASES_URL = "https://github.com/skensell201/wiring/releases/latest";
export const LATEST_RELEASE_API = "https://api.github.com/repos/skensell201/wiring/releases/latest";
/** The Development page, relative to the site base; the component adds the base. */
export const BUILD_FROM_SOURCE_PATH = "/develop/";

export const OS_NAMES: Record<Exclude<Os, "unknown">, string> = {
  mac: "macOS",
  windows: "Windows",
  linux: "Linux",
};

/** What every visitor gets before the release is known, and without JavaScript. */
export function fallbackDownload(): Download {
  return { label: "Download Wiring", href: RELEASES_URL, kind: "releases" };
}

export function detectOs(userAgent: string, platform = ""): Os {
  const s = `${platform} ${userAgent}`.toLowerCase();
  if (/iphone|ipad|android/.test(s)) return "unknown";
  if (/mac/.test(s)) return "mac";
  if (/win/.test(s)) return "windows";
  if (/linux|x11|cros/.test(s)) return "linux";
  return "unknown";
}

/** The installer for `os` among a release's assets, preferring the NSIS -setup.exe on Windows. */
export function pickAsset(assets: ReleaseAsset[], os: Os): Download {
  if (os === "linux") {
    return { label: "Build from source", href: BUILD_FROM_SOURCE_PATH, kind: "source" };
  }
  if (os === "unknown") return fallbackDownload();
  const suffixes = os === "mac" ? [".dmg"] : ["-setup.exe", ".msi"];
  for (const suffix of suffixes) {
    const asset = assets.find((a) => a.name.endsWith(suffix));
    if (asset) {
      return { label: `Download for ${OS_NAMES[os]}`, href: asset.browser_download_url, kind: "asset" };
    }
  }
  return { label: `Download for ${OS_NAMES[os]}`, href: RELEASES_URL, kind: "releases" };
}
```

```ts
/** The edges to draw, with ReplicaSets collapsed into "owns" edges when their chip is off (as the app does). */
export function visibleEdges(
  edges: EdgeDef[],
  byId: Record<string, GraphNode>,
  shown: Record<string, boolean>,
): Edge[] {
  const out: Edge[] = [];
  const seen = new Set<string>();
  const add = (a: string, b: string, t: string) => {
    const id = a + ">" + b;
    if (!seen.has(id)) {
      seen.add(id);
      out.push({ id, a, b, t });
    }
  };
  edges.forEach(([from, to, type]) => {
    const A = byId[from];
    const B = byId[to];
    if (A.kind === "ReplicaSet" && !shown.ReplicaSet) return;
    if (B.kind === "ReplicaSet" && !shown.ReplicaSet) {
      edges.forEach((f) => {
        if (f[0] === to && shown[byId[f[1]].kind]) add(from, f[1], "owns");
      });
      return;
    }
    if (shown[A.kind] && shown[B.kind]) add(from, to, type);
  });
  return out;
}

/** Columns by kind, each centred on the tallest; the size of the whole drawing. */
export function layout(
  nodes: GraphNode[],
  shown: Record<string, boolean>,
): { target: Record<string, Point>; w: number; h: number } {
  const cols: Record<number, GraphNode[]> = {};
  nodes.forEach((n) => {
    if (!shown[n.kind]) return;
    const c = KIND[n.kind].col;
    (cols[c] = cols[c] || []).push(n);
  });
  const keys = Object.keys(cols).map(Number).sort((a, b) => a - b);
  let maxRows = 0;
  keys.forEach((c) => {
    maxRows = Math.max(maxRows, cols[c].length);
  });
  const tallest = maxRows * H + (maxRows - 1) * ROWGAP;
  const target: Record<string, Point> = {};
  keys.forEach((c, ci) => {
    const list = cols[c];
    const h = list.length * H + (list.length - 1) * ROWGAP;
    const y0 = PAD + (tallest - h) / 2;
    list.forEach((n, i) => {
      target[n.id] = { x: PAD + ci * (W + COLGAP), y: y0 + i * (H + ROWGAP) };
    });
  });
  const w = PAD * 2 + Math.max(1, keys.length) * W + Math.max(0, keys.length - 1) * COLGAP;
  return { target, w, h: PAD * 2 + Math.max(tallest, H) };
}

/** A horizontal S-curve from the right side of `a` to the left side of `b`. */
export function edgePath(a: Point, b: Point): string {
  const x1 = a.x + W;
  const y1 = a.y + H / 2;
  const x2 = b.x;
  const y2 = b.y + H / 2;
  const c = Math.max(36, (x2 - x1) * 0.5);
  return `M${x1} ${y1} C${x1 + c} ${y1} ${x2 - c} ${y2} ${x2} ${y2}`;
}
```

```ts
// Tracks the timers, animation frames, listeners and observers a landing demo starts, so that
// leaving the page (VitePress swaps pages without a reload) stops all of them.

export class Scope {
  disposed = false;
  private timers = new Set<ReturnType<typeof setTimeout>>();
  private frames = new Set<number>();
  private cleanups: Array<() => void> = [];

  /** setTimeout that is cleared on dispose and never fires after it. */
  timeout(fn: () => void, ms: number): ReturnType<typeof setTimeout> {
    const id = setTimeout(() => {
      this.timers.delete(id);
      if (!this.disposed) fn();
    }, ms);
    this.timers.add(id);
    return id;
  }

  clearTimeout(id: ReturnType<typeof setTimeout> | undefined): void {
    if (id === undefined) return;
    clearTimeout(id);
    this.timers.delete(id);
  }

  frame(fn: (now: number) => void): number {
    const id = requestAnimationFrame((now) => {
      this.frames.delete(id);
      if (!this.disposed) fn(now);
    });
    this.frames.add(id);
    return id;
  }

  cancelFrame(id: number | null): void {
    if (id === null) return;
    cancelAnimationFrame(id);
    this.frames.delete(id);
  }

  /** addEventListener that is removed on dispose. */
  on<K extends keyof WindowEventMap>(target: Window, type: K, fn: (e: WindowEventMap[K]) => void): void;
  on<K extends keyof DocumentEventMap>(target: Document, type: K, fn: (e: DocumentEventMap[K]) => void): void;
  on<K extends keyof HTMLElementEventMap>(target: HTMLElement, type: K, fn: (e: HTMLElementEventMap[K]) => void): void;
  on(target: EventTarget, type: string, fn: (e: Event) => void): void {
    target.addEventListener(type, fn);
    this.cleanups.push(() => target.removeEventListener(type, fn));
  }

  /** Runs `fn` on dispose (for observers and third-party instances). */
  add(fn: () => void): void {
    this.cleanups.push(fn);
  }

  dispose(): void {
    this.disposed = true;
    this.timers.forEach((id) => clearTimeout(id));
    this.frames.forEach((id) => cancelAnimationFrame(id));
    this.timers.clear();
    this.frames.clear();
    this.cleanups.splice(0).forEach((fn) => fn());
  }
}

/** document.createElement with a class and text, as the mockup's el(). */
export function el<K extends keyof HTMLElementTagNameMap>(
  tag: K,
  cls?: string | null,
  text?: string | number | null,
): HTMLElementTagNameMap[K] {
  const e = document.createElement(tag);
  if (cls) e.className = cls;
  if (text != null) e.textContent = String(text);
  return e;
}

/** The element with this id inside `root`; throws if the markup and the script disagree. */
export function byId<T extends Element = HTMLElement>(root: ParentNode, id: string): T {
  const found = root.querySelector<T>(`#${id}`);
  if (!found) throw new Error(`landing: #${id} is missing`);
  return found;
}
```

VitePress's router handles every same-origin link click in a capturing `window` listener (`vitepress/dist/client/app/router.js`). It skips links that have a `target` attribute. Task 12's port therefore gives the landing's in-page links `target="_self"`, and this module scrolls them with the mockup's `top 24px` offset. Without that, the router would scroll them itself with the docs' 134 px header offset, and fight the smoother.

```ts
// Smooth scrolling on the landing, as on skensel.com: GSAP ScrollSmoother, skipped for
// prefers-reduced-motion. GSAP is imported here, in the browser only, so the server build never
// loads it. The landing's in-page links (href="#…") carry target="_self", which VitePress's
// router leaves alone, so this handler scrolls them.
import { Scope } from "./scope";

const OFFSET = "top 24px";

export function initSmooth(root: HTMLElement, reduced: boolean): () => void {
  const scope = new Scope();
  let smoother: { scrollTo(target: Element, smooth: boolean, position: string): void; kill(): void } | null = null;

  const scrollToHash = (hash: string, smooth: boolean) => {
    if (hash.length < 2) return false;
    const t = root.querySelector(hash);
    if (!t) return false;
    if (smoother) smoother.scrollTo(t, smooth, OFFSET);
    else t.scrollIntoView({ behavior: reduced || !smooth ? "auto" : "smooth" });
    return true;
  };

  root.querySelectorAll<HTMLAnchorElement>('a[href^="#"]').forEach((a) => {
    scope.on(a, "click", (e) => {
      if (scrollToHash(a.getAttribute("href") ?? "", true)) e.preventDefault();
    });
  });

  if (!reduced) {
    void Promise.all([import("gsap"), import("gsap/ScrollTrigger"), import("gsap/ScrollSmoother")]).then(
      ([{ gsap }, { ScrollTrigger }, { ScrollSmoother }]) => {
        if (scope.disposed) return;
        gsap.registerPlugin(ScrollTrigger, ScrollSmoother);
        smoother = ScrollSmoother.create({
          wrapper: root.querySelector("#smooth-wrapper"),
          content: root.querySelector("#smooth-content"),
          smooth: 1.2,
          smoothTouch: false,
          effects: true,
        });
        scope.add(() => {
          smoother?.kill();
          smoother = null;
```

### Task 12: The landing page, generated from the mockup (TDD for the server render)

`site/index.md` becomes `layout: false` plus `<Landing />`. In VitePress 1.6.4 the default theme's `Layout.vue` renders `<Content />` alone when `frontmatter.layout === false` (`<div v-if="frontmatter.layout !== false" class="Layout">…<Content v-else />`), so the page has no VitePress nav, sidebar or footer. This was verified in a scratch build: the built `index.html` has no `VP…` class.

The page's markup and CSS are not copied by hand. `site/scripts/port-landing.py` generates them from the committed mockup (Task 9, Step 1), so the landing follows whatever the approved mockup is at execution time, and can be regenerated after a later mockup edit. Do not edit its outputs by hand: edit the mockup and run the script again.

**What the port does** (each rule asserts that its match exists, so a mockup with a different structure stops the port with a message):
- **CSS** (`<style>` → `site/.vitepress/theme/landing.css`):
  - Every selector is prefixed with `.wl`, the landing's root element. That includes inside `@media` blocks, and covers `*`, `a`, `button`, `h1`, `h2`, `section`, `table` and `footer`.
  - The declarations of `:root`, `html` and `body` merge into one `.wl { … }` block. `margin` and `-webkit-text-size-adjust` are dropped (VitePress already sets both), and `overflow-x` becomes `clip`.
  - `@keyframes x` becomes `@keyframes wl-x`, and every `animation: x` follows.
  - `font-family: Geist,` becomes `"Geist Variable", Geist,` and `"Geist Mono"` becomes `"Geist Mono Variable", "Geist Mono"`. These are the self-hosted fonts; the Google Fonts `<link>`s are not ported.
  - Three rules undo VitePress's base reset where it differs from the browser defaults the mockup was designed on: `.wl p { margin: 1em 0 }`, `.wl h3 { line-height: inherit }`, `.wl b { font-weight: bolder }`.
- **Markup** (`<body>` up to the first `<script>`; comments dropped):
  - The element with `id="graph-demo"` → `LandingGraph.vue` (with `ref="root"`); `<LandingGraph />` takes its place.
  - The element with `id="table-demo"` → `LandingTable.vue`; `<LandingTable />` takes its place.
  - `<section id="contacts">` → `LandingContacts.vue`, its Copy button bound to `copy()` and `copied`; `<LandingContacts />` takes its place.
  - The hero's `<div class="cta">` (the one holding `id="dl"`) is replaced by `<LandingDownload />`, and the `<p id="other">` is removed. `LandingDownload.vue` renders both.
  - The rest, wrapped in `<div ref="root" class="wl">`, → `Landing.vue`.
- **Links:**
  - Each feature card goes to its guide page, by its `<h3>` title: Live graph → `/guide/graph`, Logs… → `/guide/logs-terminal`, Rollouts… → `/guide/actions`, Metrics → `/guide/metrics`, Namespaces… → `/guide/namespaces`, Custom resources… → `/guide/custom-resources`, Automatic updates → `/guide/updates`. Tables and YAML keeps `#tables`, the demo below. This works whether the card points at a `#docs-…` placeholder or at the GitHub README (the deployed interim copy uses `https://github.com/skensell201/wiring#readme`).
  - `#docs` and the README link (the nav's and footer's Docs, Read the docs) → `/guide/getting-started`. There is no `/guide/` index page; Getting started is the guide's first page.
  - `…/wiring#build-from-source` → `/develop/`.
  - Every remaining in-page link (`href="#x"`) gets `target="_self"`, and its target id must exist.
  - `src="mark.svg"` → `src="/mark.svg"`.
  - A leftover `#docs-…` or `#readme` link, or a link inside a demo, stops the port.
- **The mockup's `<script>`** is not read. Its logic is Tasks 9 and 10.

Everything else (text, classes, ids, section order) is the mockup's. Nothing reads `window`, `document` or `navigator` outside `onMounted` or a click handler, so the server render works; the test below runs in Node, where they do not exist. Only `LandingDownload` and `LandingContacts` have reactive state, and only in their own bindings. Vue therefore never patches the demos' markup after hydration, and the scripts' DOM changes are safe.

```python
#!/usr/bin/env python3
"""Ports the approved landing mockup into the site, mechanically.

Reads docs/superpowers/specs/2026-10-06-landing-mockup.html and writes:
  site/.vitepress/theme/landing.css                 the mockup's <style>, scoped under .wl
  site/.vitepress/theme/components/Landing.vue       the page (nav, hero, sections, footer)
  site/.vitepress/theme/components/LandingGraph.vue  the #graph-demo block
  site/.vitepress/theme/components/LandingTable.vue  the #table-demo block
  site/.vitepress/theme/components/LandingContacts.vue  the #contacts section
The mockup's <script> is not read: its logic lives in the hand-ported TypeScript modules in
site/.vitepress/theme/landing/. Every match is asserted, so a mockup that no longer has the
expected structure stops the port instead of producing a half-ported page.
Run from the repository root: python3 <this file>
"""
import re
from pathlib import Path

SRC = Path("docs/superpowers/specs/2026-10-06-landing-mockup.html")
THEME = Path("site/.vitepress/theme")
html = SRC.read_text()


def one(pattern, text, flags=re.S):
    found = list(re.finditer(pattern, text, flags))
    assert len(found) == 1, f"{pattern!r}: expected 1 match, found {len(found)}"
    return found[0]


# ---------------------------------------------------------------- CSS

def parse(s):
    """Top-level CSS nodes: comments, rules, @media blocks (parsed recursively), @keyframes."""
    out, i = [], 0
    while i < len(s):
        if s[i].isspace():
            i += 1
            continue
        if s.startswith("/*", i):
            j = s.index("*/", i) + 2
            out.append(("comment", s[i:j]))
            i = j
            continue
        j = s.index("{", i)
        prelude = " ".join(s[i:j].split())
        depth, k = 0, j
        while True:
            if s[k] == "{":
                depth += 1
            elif s[k] == "}":
                depth -= 1
                if depth == 0:
                    break
            k += 1
        body = s[j + 1:k]
        i = k + 1
        if prelude.startswith(("@media", "@supports")):
            out.append(("media", prelude, parse(body)))
        elif prelude.startswith("@keyframes"):
            out.append(("keyframes", prelude, " ".join(body.split())))
        else:
            assert not prelude.startswith("@"), f"unexpected at-rule {prelude}"
            out.append(("rule", prelude, " ".join(body.split())))
    return out


def decls(body):
    return [tuple(p.strip() for p in d.split(":", 1)) for d in body.split(";") if d.strip()]


css = one(r"<style>(.*?)</style>", html).group(1)
for old, new in [('"Geist Mono"', '"Geist Mono Variable", "Geist Mono"'),
                 ("font-family: Geist,", 'font-family: "Geist Variable", Geist,')]:
    assert old in css, f"font {old!r} not found"
    css = css.replace(old, new)

nodes = parse(css)
keyframes = [re.match(r"@keyframes\s+([\w-]+)", n[1]).group(1) for n in nodes if n[0] == "keyframes"]
assert keyframes, "no @keyframes"

# :root, html and body all become the declarations of .wl, the landing's root element.
root = {}
for kind, prelude, *rest in nodes:
    if kind == "rule" and prelude in (":root", "html", "body"):
        for prop, value in decls(rest[0]):
            if prop in ("margin", "-webkit-text-size-adjust"):
                continue  # VitePress already has both on the real html and body
            if prop == "overflow-x":
                value = "clip"
            root[prop] = value
    elif kind == "rule":
        assert not re.search(r"(^|[\s,])(html|body)\b", prelude), f"html/body in {prelude}"


def rename_animations(body):
    for name in keyframes:
        body = re.sub(rf"(animation(?:-name)?\s*:\s*){name}\b", rf"\1wl-{name}", body)
    return body


def scope(selectors):
    return ", ".join(".wl " + s.strip() for s in selectors.split(","))


def emit(nodes, indent=""):
    lines = []
    for kind, prelude, *rest in nodes:
        if kind == "comment":
            lines.append(indent + prelude)
        elif kind == "rule" and prelude in (":root", "html", "body"):
            continue
        elif kind == "rule":
            lines.append(f"{indent}{scope(prelude)} {{ {rename_animations(rest[0])} }}")
        elif kind == "keyframes":
            name = re.match(r"@keyframes\s+([\w-]+)", prelude).group(1)
            lines.append(f"{indent}@keyframes wl-{name} {{ {rest[0]} }}")
        else:
            lines.append(f"{indent}{prelude} {{")
            lines.extend(emit(rest[0], indent + "  "))
            lines.append(indent + "}")
    return lines


root_block = ".wl {\n" + "".join(f"  {p}: {v};\n" for p, v in root.items()) + "}"
landing_css = "\n".join([
    "/* The landing page (site/index.md, layout: false), generated from the approved mockup",
    "   (docs/superpowers/specs/2026-10-06-landing-mockup.html). Every rule is scoped under .wl, the",
    "   landing's root element, and the keyframes are prefixed wl-, so nothing reaches the docs. */",
    root_block,
    "/* Undo the parts of VitePress's base reset (theme-default/styles/base.css) that differ from",
    "   the browser defaults the mockup was designed on. */",
    ".wl p { margin: 1em 0; }",
    ".wl h3 { line-height: inherit; }",
    ".wl b { font-weight: bolder; }",
    *emit(nodes),
]) + "\n"
(THEME / "landing.css").write_text(landing_css)

# ---------------------------------------------------------------- markup

page = one(r"<body>(.*?)<script", html).group(1)
page = re.sub(r"<!--.*?-->", "", page, flags=re.S)


def element(text, open_re):
    """(start, end) of the element whose opening tag matches open_re, nesting included."""
    m = one(open_re, text)
    tag = re.match(r"<(\w+)", m.group(0)).group(1)
    depth = 0
    for t in re.finditer(rf"<(/?){tag}\b[^>]*>", text[m.start():]):
        depth += -1 if t.group(1) else 1
        if depth == 0:
            return m.start(), m.start() + t.end()
    raise AssertionError(f"unclosed {open_re}")


def cut(text, open_re, replacement):
    a, b = element(text, open_re)
    return text[:a] + replacement + text[b:], text[a:b]


page, graph = cut(page, r'<div[^>]*\bid="graph-demo"[^>]*>', "<LandingGraph />")
page, table = cut(page, r'<div[^>]*\bid="table-demo"[^>]*>', "<LandingTable />")
page, contacts = cut(page, r'<section[^>]*\bid="contacts"[^>]*>', "<LandingContacts />")
page, _ = cut(page, r'<div class="cta">(?=\s*<a[^>]*\bid="dl")', "<LandingDownload />")
page, _ = cut(page, r'<p[^>]*\bid="other"[^>]*>', "")
assert 'id="dl"' not in page and 'id="other"' not in page

graph = graph.replace("<div ", '<div ref="root" ', 1)
table = table.replace("<div ", '<div ref="root" ', 1)
COPY = '<button class="copy" id="copy-mail" type="button" aria-label="Copy email address">Copy</button>'
assert contacts.count(COPY) == 1, "the Copy button changed"
contacts = contacts.replace(
    COPY,
    '<button class="copy" :class="{ ok: copied }" id="copy-mail" type="button" '
    'aria-label="Copy email address" @click="copy">{{ copied ? "Copied" : "Copy" }}</button>',
)

DOCS = "/guide/getting-started"
CARDS = {  # feature card title (start) -> its page; Tables and YAML points at the demo below
    "Live graph": "/guide/graph",
    "Tables and YAML": "#tables",
    "Logs": "/guide/logs-terminal",
    "Rollouts": "/guide/actions",
    "Metrics": "/guide/metrics",
    "Namespaces": "/guide/namespaces",
    "Custom resources": "/guide/custom-resources",
    "Automatic updates": "/guide/updates",
}
README = "https://github.com/skensell201/wiring#readme"
all_ids = set(re.findall(r'\bid="([\w-]+)"', page + graph + table + contacts))


def links(text):
    def card(m):
        title = re.sub(r"<[^>]+>", "", m.group(3))
        hits = [href for start, href in CARDS.items() if title.startswith(start)]
        assert len(hits) == 1, f"no page for the feature card {title!r}"
        return f'<a class="card" href="{hits[0]}"{m.group(2)}<h3>{m.group(3)}</h3>'

    text, cards = re.subn(r'<a class="card" href="([^"]*)"(.*?)<h3>(.*?)</h3>', card, text, flags=re.S)
    text = re.sub(r'href="(#docs|' + re.escape(README) + r')"', f'href="{DOCS}"', text)
    text = text.replace('href="https://github.com/skensell201/wiring#build-from-source"', 'href="/develop/"')
    leftover = re.findall(r'href="(#docs-[\w-]*|[^"]*#readme)"', text)
    assert not leftover, f"unmapped docs links {leftover}"
```
